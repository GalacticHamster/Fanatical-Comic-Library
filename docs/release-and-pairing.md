# Release and pairing verification (FAN-07 / FAN-09 / FAN-11 / FAN-14)

Current official discovery and Advanced settings are documented in [companion pairing](companion-pairing.md). Dated verification below describes earlier manual-only builds; official Gecko identities now remain trusted when duplicate manual entries are removed.

Run node scripts/package-release.mjs to build dist/FanaticalLibrary-<version>.zip, its SHA-256 file and a file/hash report. The explicit runtime-files.json allowlist contains only the manifest and required runtime assets. Dependency validation checks manifest entries, module imports, HTML scripts/styles and CSS references. Real paths cannot leave the repository through symlinks/junctions. ZIP order, timestamps and normalized text line endings are fixed. Tests, wrappers unused by the runtime, documentation, exports, profiles, reconnaissance and Git history are excluded. No adjacent repo is required to build it.

Run node --test tests for regressions and node tests/browser-check.mjs --release for the actual packaged runtime in isolated Chrome fixtures. Projection tests call the same self-contained order importer that Chrome serializes into the page; the standalone bundle parser is also a thin wrapper around the live parser. Package tests check syntax, reproducibility across checkouts, missing dependencies, checksum tampering and unsafe paths.

Pairing Test link checks both PING and GET_STATUS, validates version/success and discloses supported media, reviewed contents and entitlement reminders. An unsuccessful or malformed lookup stays incomplete and is not an available zero-match result. Transport details and returned error strings are not displayed. Software comparisons require affirmative software capability; older versions keep them local. Capability failures remain unconfirmed.

Local Fanatical purchases are authoritative. Requests exclude central Fanatical copies, and a returned copy from an older/unfiltered API is review-only, never Owned elsewhere or owned contents. If local and central snapshots disagree, rescan the local Orders importer. Evidence explanations name the two sources without merging them.

Checks use synthetic provider responses and isolated browser profiles, not a signed-in personal account. They verify shipped behavior but cannot certify an unobserved real large-account response. Increase the manifest version before a published store update.

Badge layout fixtures include Fanatical's observed `.faux-block-link button { position: relative; z-index: 3; }` rule, cover clipping, and native Pick & Mix New to bundle labels. Tests check computed placement, visible cover bounds, cover outlines and click targets, rather than only checking that a badge exists. The clickable inspector conversion previously allowed that provider rule to move badges below the cover; the Not checked state also lacked its border and native-label offset. On 2026-10-03, anonymous Chrome inspection of the Valiant Heroic Comic Collection reproduced both failures. Scoped placement now keeps all six badge states inside the top of the cover, with a two-pixel outline, while retaining keyboard access to evidence.

Run `node tests/browser-check.mjs --release --slow-central` and add `--firefox` for delayed-response checks on standard and Pick & Mix cards. Valid 4.5-second replies must complete, preserving local purchases, external ownership, panel size/corner and badge geometry. Both lookups and capability checks allow 30 seconds per request, replacing the former 3.5-second lookup and 5-second capability deadlines. A failed lookup exposes "Retry Galactic Library checks" beside its status. Retry requests missing results, preserves completed checks, keeps the settled summary visible, ignores duplicate clicks and clears failure labels after success. Core tests advance the finite deadline without waiting and verify that late replies cannot mutate settled failure results.

Additional 2026-10-03 verification restored a user-supplied 14,081-record GL export into a disposable Chrome profile and sent the actual 40 public Valiant bundle requests through the installed FAN and GL extensions. Idle requests completed in about 1.6 seconds with Possible candidates for 25 titles. Six concurrent GL database reads reproduced all 40 requests failing at the former deadline; the 30-second deadline completed all 40 under the same synthetic load in about 11.3 seconds. This verifies recovery under load, not that the user's original timeout had exactly that workload. Longer deadlines preserve correct results but do not speed up GL's database reads. No personal export or library titles were added to repository fixtures.

Run npm run runtime-check to install the validated ZIP into a disposable Chrome profile and exercise the real content-script -> service-worker -> MAIN importer. The test locally fulfills every request on its synthetic Fanatical tab: 200 orders/10 pages full scan, 201 orders/11 pages quick scan fetching one new detail, and a broken-pagination scan preserving the last successful snapshot. It also exercises the actual queued writer, wishlist/backup restore and sender checks. No live account or personal Chrome profile is used.

Run npm run runtime-check:central when the adjacent GalacticLibrary repository is available. Both validated packages are installed in the disposable profile. Tests verify rejection before allowlisting, successful capabilities/software lookup with Fanatical copies excluded, and reported central reminder dates consumed by Fanatical settings. Native Fanatical records currently expose activation reminders without a key-expiry field; Humble records supply reported key expiries. Unknown dates remain unknown. The adjacent repository is an optional integration-test dependency, never a build/runtime dependency.

Final verification on 2026-10-01: all 167 regression tests, all nine packaged Chrome DOM fixtures and ten installed Chrome checks including real central pairing passed. Synthetic 5,000-order/100-page coverage verifies the supported pagination contracts; the real large-account response shape still needs a capture before claiming live-provider certification.
